# Markdown 文件可靠写入 Skill

## 核心原则

当需要写入或编辑 .md 文件时，遵循以下策略确保成功：

## 写入策略

### 1. 小文件（< 50 行）
- 直接使用 fs_write 一次性写入全部内容

### 2. 中等文件（50-150 行）
- 使用 fs_write 写入前 50 行
- 使用 fs_append 追加剩余内容（每次不超过 50 行）

### 3. 大文件（> 150 行）
- 使用 fs_write 写入前 50 行
- 使用多次 fs_append 追加内容，每次追加不超过 50 行
- 确保每次追加的内容在逻辑上是完整的（不要在表格中间、代码块中间断开）

## 编辑策略

### 局部修改
- 优先使用 str_replace 进行精确替换
- 确保 oldStr 足够唯一，包含上下文

### 大段替换或重写
- 如果替换内容超过 50 行，分步操作：
  1. 先用 str_replace 替换为一个占位标记
  2. 再用 str_replace 将占位标记替换为新内容的第一部分
  3. 在第一部分末尾后用 str_replace 追加后续内容

### 追加内容
- 使用 fs_append 在文件末尾追加
- 每次追加不超过 50 行

## 断点规则

分次写入时，在以下位置断开是安全的：
- 章节标题（#、##、###）之前
- 空行处
- 表格结束后
- 列表项之间（同级别）
- 代码块结束之后

以下位置不要断开：
- 表格中间（表头和数据行之间）
- 代码块内部
- 多行列表项的中间
- front-matter 内部

## 执行检查

每次写入/追加后：
- 不需要额外验证，信任工具的成功响应
- 如果工具报错，减少单次写入量后重试
