## 原始需求

> 可以管理儿童的照片、视频，自动管理和调入调出

---

## 提取意图

在儿童工作区中提供**照片/视频管理能力** — 家长把孩子的照片视频导入后，系统自动整理（按时间/事件/人物），agent 能在合适的时机调出来展示（如"看看你去年生日的照片"）。

核心价值：
1. **自动整理** — 不用家长手动分类相册
2. **智能调取** — 儿童语音说"我想看海边的照片" → agent 自动找到并展示
3. **成长记录** — 照片/视频按时间轴串联成成长故事

## 开放问题

| # | 模块 | 问题 | AI 猜测 | 答案 |
|---|------|------|---------|------|
| 1 | 用户与现状 | 照片/视频的来源是什么？家长手动导入文件夹、从手机同步、还是从云盘拉取？ | 家长手动导入本地文件夹（指定目录自动扫描） | |
| 2 | 用户与现状 | 目前家长怎么管理孩子的照片？痛点是什么（太多找不到？没时间整理？） | 手机里几千张混在一起，想找某次活动的照片要翻很久 | |
| 3 | 范围与影响 | "自动管理"具体做什么？按日期分文件夹、按人脸聚类、按场景标签、还是全部？ | 按日期 + 按场景标签（AI 识别内容：生日/旅行/学校） | |
| 4 | 范围与影响 | "调入调出"是什么意思？儿童语音查询调出，还是 agent 主动在特定时间展示（如"今天是你的生日，看看去年的照片"）？ | 两者都有：语音查询 + agent 主动推送 | |
| 5 | 业务规则 | 照片/视频存储在哪？本地磁盘、工作区目录、还是需要支持 NAS/云盘？ | 本地工作区目录（数据本地化原则） | |
| 6 | 业务规则 | AI 图片理解用什么方案？本地模型（CLIP/BLIP）识别标签，还是云端视觉 API（GLM-4V）？ | 本地大模型 + 人工标签 | 本地大模型辅助标签（Ollama 视觉模型）+ 人工确认/修正。敏感数据不走云端 API，结合 #063 本地模型路由 |
| 7 | 业务规则 | 隐私安全考虑 — 儿童照片是敏感数据，是否需要加密存储或限制 AI 上传分析的范围？ | 标签分析可选（家长决定是否启用 AI 识别），照片本身不上传云端 | |

## 核心场景

### 场景 1：自动整理
```
家长：把 D:/照片/2026 这个文件夹导入
Agent：扫描到 1,247 张照片、38 个视频
      → 按日期创建 12 个月份分组
      → 本地模型（LLaVA）自动识别场景标签（海边/生日/学校）
      → 家长确认或修正标签
      → 完成，你可以在儿童工作区里浏览
```

### 场景 2：儿童语音调取
```
小孩："岛主，我想看海边的照片"
Agent：找到 23 张海边相关照片 → 以幻灯片形式展示
      "这是去年暑假你在海边堆沙堡的照片哦～"
```

### 场景 3：agent 主动推送
```
（检测到今天是孩子生日）
Agent："今天是你的生日！看看去年生日你许愿的样子～"
      → 自动展示去年生日标签的照片
```

## 备注

与现有系统的关系：
- **#086 儿童工作区** — 照片管理是工作区的一个功能模块
- **#085 语音交互** — "我想看 XX 照片"通过语音触发
- **#084 生命周期** — agent 可以基于照片时间线理解孩子的成长（"你现在比去年高了好多"）
- **数据本地化原则** — 照片不上传云端，标签缓存在本地

技术参考：
- Google Photos 的自动分类（按日期+手动相册）
- 本地文件元数据（EXIF 日期/GPS）做基础分组
- 本地视觉模型（Ollama + LLaVA/MiniCPM-V）做图片理解标签
- 标签系统：本地模型预标 + 家长确认/修正
- #063 智能模型路由 — 敏感数据走本地模型，普通任务走云端
