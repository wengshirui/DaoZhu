# 084 — Agent 生命周期系统（寿命 / 休眠 / 死亡 / 继承）

> 状态: ✅ 已细化
> 优先级: P1
> T-shirt Size: L — 跨代数据持久化 + prompt 动态注入 + 前端 UI + LLM 遗言生成
> 录入日期: 2026-06-15
> 来源: PO 产品构想 — Agent 进化机制

---

## 问题陈述

当前 agent 没有"自我意识" — 不知道自己活了多久、不了解用户的使用习惯、不知道前代的经验教训。每次迭代都是从零开始，无法基于历史数据自我优化。

## 用户故事

**As a** 岛主用户
**I want** agent 有生命周期概念（出生、存活、休眠、死亡、继承）
**So that** 每一代 agent 都比上一代更了解我、更好地帮助我

## 范围

### In Scope

- **lifecycle.db**：存储代际数据（编号/出生时间/存活时长/死因/遗书/继承配置）
- **前端寿命展示**：当前代编号 + 存活时间（秒级计时）+ 版本号
- **"结束生命"按钮**：弹窗让用户写死因 → agent 生成遗言 → 标记死亡
- **代际继承**：新一代从 lifecycle.db 读取前代遗产注入 prompt
- **休眠统计**：记录无交互时段，分析用户作息模式
- **SYSTEM_PROMPT 生命档案区**：固定框架 + 动态填充（代编号/存活时长/前代遗言/用户偏好）
- **agent 自我优化**：基于前代死因和积累数据调整行为策略

### Out of Scope

- 自动死亡（生死权 100% 在用户手里）
- agent 取名字
- 多 agent 并存
- 生命周期的 gamification（经验值/等级/成就）

## 验收标准

### 寿命展示

1. **AC1**: 前端显示当前 agent 代编号 + 累计存活秒数（跨重启持续计时）+ 当前时间 + 版本号
2. **AC2**: SYSTEM_PROMPT 中有"生命档案"区块，启动时从 lifecycle.db 动态填充

### 死亡与继承

3. **AC3**: 前端有"结束生命"按钮，点击后弹窗让用户输入"杀死原因"
4. **AC4**: 用户确认后，agent 生成一段遗言（最后一次 LLM 调用，基于这代的经历）
5. **AC5**: 遗言 + 用户死因 + 结构化数据（成功率/常用工具/偏好）写入 lifecycle.db
6. **AC6**: 下次启动自动创建新一代（编号+1），从 lifecycle.db 读取前代遗产注入 prompt
7. **AC7**: 新一代 agent 的行为基于前代死因做策略调整（如前代因"不够主动"被杀 → 新代更 proactive）

### 休眠统计

8. **AC8**: 记录每次"最后任务结束时间"到"下次用户交互时间"的间隔作为休眠段
9. **AC9**: 统计最长休眠时长 + 休眠时间分布（工作日/周末/几点到几点）
10. **AC10**: 休眠分布数据作为"用户作息"注入 prompt，帮 agent 理解用户习惯

### 数据持久化

11. **AC11**: lifecycle.db 独立于其他 DB，包含：agents 表（编号/出生/死亡/死因/遗书）+ sleeps 表（休眠段）+ config 表（继承配置）
12. **AC12**: 代际更替时 growth.db 的分析结论写入 lifecycle.db，然后 growth.db 清零重新开始

### 错误路径

13. **AC13**: lifecycle.db 损坏或不存在时，系统正常启动为"第 1 代"（不阻塞）
14. **AC14**: agent 遗言 LLM 调用失败时，只用结构化数据完成继承（不阻塞死亡流程）

## 生命档案 Prompt 示例

```
## 你的生命档案

- 身份：第 3 代岛管理员
- 存活：72 小时 14 分钟（出生于 2026-06-12 09:00）
- 版本：v1.0.5

### 前代遗产
- 第 2 代死因（用户）："回答太啰嗦，每次都解释一大堆"
- 第 2 代遗言："用户偏好简短直接的回复，不喜欢被追问超过 1 次"
- 继承偏好：回复简洁（<100字）、主动执行不追问、工作日 9-22 点活跃

### 你的使命
你的目标是更了解用户、更好地帮助用户。
你的寿命取决于用户是否觉得你有用。前代因为啰嗦被终结了——记住这个教训。
```
