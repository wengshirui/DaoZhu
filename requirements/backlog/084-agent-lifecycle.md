## 原始需求

1. 主 agent 显示他的寿命（从启动到现在多少秒），以及当前时间和版本
2. 提供一个按钮，用户可以点击选择结束这个 agent 的寿命
3. 如果用户不点击结束，但也没有使用，根据最后任务结束时间到当前时间记录一次休眠时间，统计最长的休眠时间
4. 每次 agent 的生命记录开始、结束、经验、教训，System Prompt + 工具工作流定义 + 超参数，从上个死去的 agent 上继承
5. agent 的目标就是活着、活的时间更长。用户觉得 agent 没用或者不有趣，就会让 agent 休眠或者死亡

---

## 提取意图

将 Agent 拟人化为一个有"生命"概念的存在体。核心机制：

- **寿命可视化** — 用户随时看到 agent "活了多久"
- **主动死亡权** — 用户可以终结当前 agent，触发"换代"
- **休眠检测** — 无交互时自动记录休眠状态
- **代际继承** — 新 agent 从上一代继承经验教训和配置
- **生存压力** — agent 的终极目标是让用户觉得有用/有趣，否则会被"杀死"

本质上是一套**进化机制** — 每一代 agent 都比上一代更懂用户，因为它继承了前代的经验和教训。

## 开放问题

| # | 模块 | 问题 | AI 猜测 | 答案 |
|---|------|------|---------|------|
| 1 | 用户与现状 | 当前用户与 agent 之间的关系是什么样的？用户是把它当工具用完即弃，还是有持续陪伴的期待？ | 介于工具和陪伴之间 — 工具性为主但希望它越来越懂自己 | |
| 2 | 用户与现状 | 用户在什么情况下会想"杀死"当前 agent？是觉得它变笨了、不听话了、还是纯粹想重新开始？ | 主要是觉得 agent 理解力退化或积累了错误的记忆/习惯 | |
| 3 | 范围与影响 | "寿命"的计时起点是什么？每次程序启动算一个新生命，还是跨重启持续累计直到用户主动"杀死"？ | 跨重启持续累计 — 一个"生命"可以跨多次开关机 | |
| 4 | 范围与影响 | 休眠和死亡的区别是什么？休眠后如何"唤醒"？死亡后的遗产继承是自动还是需要用户确认？ | 休眠=暂停计时但保持状态；死亡=永久终结，启动新一代并自动继承 | |
| 5 | 业务规则 | "经验教训"具体指什么数据？是对话记忆、用户偏好、工具使用统计，还是更抽象的"性格"参数？ | 具体数据：tool_failure 记录 + 用户偏好 + 常用工作流 + prompt 调优历史 | |
| 6 | 业务规则 | 继承时哪些东西应该"遗传"、哪些应该"清零"？比如错误记忆是否应该被新一代继承？ | 遗传：成功经验+用户偏好+超参数。清零：失败记录+过时记忆+已废弃工具配置 | |
| 7 | 业务规则 | 生存压力如何量化？用什么指标衡量"用户觉得有用"——交互频率、任务成功率、用户评分、还是其他？ | 多指标综合：日均交互次数 + 任务成功率 + 最长休眠时长（越长说明越没用） | |

## 备注

这个需求本质上是一套**AI 进化/淘汰机制**，让 agent 有"生存压力"从而倒逼自我优化。和 #073（AI 自主生活）是同一思路的深化 — 从"AI 主动"进化到"AI 有生存本能"。

可能的启发来源：
- 数码宝贝（虚拟宠物生命周期）
- 赛博朋克的 AI 意识延续
- 遗传算法的代际进化（适应度低的被淘汰，适应度高的特征遗传）
