## 问题陈述

Agent 不应该只是一个被动的工具执行器。它应该像一个真正的管家一样**越用越懂用户**：
- 知道用户经常做什么（高频模式）
- 知道自己哪里做得不好（从撤回、重复提问中学习）
- 能主动改进服务方式（而不是等用户告诉它）

当前的"复盘"只做了工具错误分析，这只是冰山一角。真正的价值是 **Agent 成长**。

## 用户故事

**As a** 岛主用户
**I want** AI 管家能自动从我的使用中学习和成长
**So that** 它越来越懂我，服务越来越精准，不用我反复教它

## 三个成长维度

### 维度 1：理解用户（从对话中学习）

- 分析近 N 天对话，提炼用户的高频需求模式
- 发现用户偏好（"这个用户喜欢简洁回复""经常在晚上用""主要用待办和记账"）
- 自动丰富 user_profile（不用 LLM 每轮提取，定时批量分析更高效）

### 维度 2：优化自己（从错误中学习）

- 用户撤回 = 对回答不满意 → 分析撤回的上下文，记录"什么情况下回答不好"
- 工具调用低效（同一任务调了 5 次才成功）→ 记录高效路径
- 重复被问同样的问题 → 自动创建知识条目或技能

### 维度 3：主动服务（从模式中推断）

- 用户每天早上问天气 → 自动创建定时任务"每天 8:00 查天气"
- 用户每周五记周报 → 主动提醒"今天周五，需要帮你整理周报吗？"
- 用户创建了工作区但没怎么用 → 主动问"XX 工作区还需要调整吗？"

## 安全原则

```
Agent 成长可以做的：
✅ 读取对话历史和日志（只读）
✅ 更新 user_profile（丰富画像）
✅ 添加 knowledge 条目（积累经验）
✅ 清理过期/错误的知识
✅ 禁用/启用非核心工具
✅ 建议创建定时任务（用户确认后执行）

Agent 成长不能做的：
❌ 修改 daozhu/ 源码
❌ 禁用核心工具
❌ 删除用户对话历史
❌ 修改密钥配置
❌ 未经确认就执行🟡🔴级建议
```

## 复盘质量原则（来自 2026-06-03 教训）

```
分析必须做的：
✅ 看具体错误信息，不只看数字
✅ 区分"工具 bug" vs "AI 用错了"（后者改 prompt 不改工具）
✅ 核心工具永不建议禁用
✅ 去重：已处理的不重复建议
✅ 归类错误模式（404？参数错？超时？）

分析不能做的：
❌ 看到失败率高就无脑建议禁用
❌ 不看错误详情就下结论
❌ 给出无法执行的笼统建议
```
