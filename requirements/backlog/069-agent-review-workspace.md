## 问题陈述

#062 规划了"AI 定时自我复盘"的后台逻辑，但复盘结果、优化建议、执行记录需要一个
可视化的系统工作区来承载。用户需要能看到 AI 做了哪些自我优化、哪些建议生效了、
哪些被忽略了。

**核心难点**：AI 优化后如何不影响项目稳定、不和项目代码冲突？

设计原则：
- 复盘只产出**建议**（记录在工作区中），不自动修改代码
- 建议分级：自动执行（安全的，如清理过期记忆）/ 需确认（如禁用失败工具）
- 涉及代码的建议只记录不执行（人工判断后手动实施）

## 用户故事

**As a** 岛主用户
**I want** 看到 AI 管家的自我复盘报告和优化建议
**So that** 我知道 AI 在持续进化，并能审核哪些优化可以执行

## 范围

### In Scope

- 系统工作区（`category: system`）
- 复盘报告列表：日期 + 发现的问题 + 建议（每日一条）
- 建议分级：
  - 🟢 自动执行（清理过期记忆、更新使用统计）
  - 🟡 需确认（禁用高失败率工具、调整配置）
  - 🔴 仅记录（涉及代码修改、架构变更）
- 执行记录：哪些建议已执行、何时、结果如何
- 复盘触发：配合 #067 定时任务（每日一次）

### Out of Scope

- AI 自动修改项目源码（太危险，只记录建议）
- 复盘算法的训练/微调
- 跨项目的复盘比较

## 验收标准

1. **AC1**: 存在"Agent 复盘"系统工作区，打开后显示复盘报告列表
2. **AC2**: 每条报告包含：日期、分析摘要、建议列表（分级标记）
3. **AC3**: 🟢级建议自动执行后显示"已执行"标记和结果
4. **AC4**: 🟡级建议显示"确认执行"按钮，用户点击后执行
5. **AC5**: 🔴级建议只显示内容，不提供执行按钮（标记为"仅供参考"）
6. **AC6**: 复盘过程不修改 daozhu/ 源码目录下的任何文件

## 业务价值

- 让 AI 的"进化"可见可控（不是黑箱）
- 安全边界明确：代码级变更永远需要人工介入
- 为用户建立信任：AI 在变好，但不会失控

## 安全原则（重要）

```
AI 复盘可以做的：
✅ 读取记忆和日志
✅ 调用 LLM 分析模式
✅ 写入建议到复盘工作区数据库
✅ 自动执行：清理过期记忆、更新统计
✅ 自动执行：禁用/启用非核心工具（用户可恢复）

AI 复盘不能做的：
❌ 修改 daozhu/ 下的 Python 源码
❌ 修改 workspace.json 配置
❌ 删除工作区
❌ 修改 .env 密钥
❌ 推送代码到 git
❌ 禁用核心工具（list_workspaces, call_workspace_api 等）
```

## 复盘质量原则（来自 2026-06-03 教训）

```
复盘必须做的：
✅ 看具体错误信息，不只看数字（失败率）
✅ 区分"工具有 bug" vs "AI 用错了工具"（后者不应该禁用工具）
✅ 核心工具永远不建议禁用，只建议排查原因
✅ 已处理过的建议不重复出现（去重）
✅ 分析错误模式（全是 404？全是参数错？连接超时？）

复盘不能做的：
❌ 看到失败率高就无脑建议禁用
❌ 不看错误详情就下结论
❌ 给出无法执行的笼统建议（如"建议优化"）
❌ 重复给出已经处理过的建议
```
