## 原始需求

> 可以语音唤醒 agent，可以和 agent 进行对话

---

## 提取意图

让用户能通过**语音**与 agent 交互，而不仅限于打字。包含两个核心能力：
1. **语音唤醒** — 用户说出唤醒词（如"岛主"），agent 开始监听
2. **语音对话** — 用户说话 → 语音转文字 → agent 处理 → 回复转语音播放

本质上是为 agent 增加"耳朵"和"嘴巴"。

## 开放问题

| # | 模块 | 问题 | AI 猜测 | 答案 |
|---|------|------|---------|------|
| 1 | 用户与现状 | 用户在什么场景下会想用语音而不是打字？是解放双手（做饭/开车），还是更自然的交互体验？ | 主要是解放双手场景 + 桌面宠物交互更自然 | |
| 2 | 用户与现状 | 语音交互是主力交互方式，还是文字的补充（偶尔用）？这决定了投入多少精力做语音体验 | 补充性质 — 文字仍是主力，语音是锦上添花 | |
| 3 | 范围与影响 | 唤醒词是固定的（如"岛主"），还是用户可自定义？是否需要离线唤醒（不联网也能响应）？ | 固定唤醒词"岛主" + 需要离线唤醒（基本体验不依赖网络） | |
| 4 | 范围与影响 | 语音对话是单轮（说一句→回一句→结束监听），还是连续对话（保持监听直到用户说"结束"）？ | 单轮为主，但用户可手动切换到连续模式 | |
| 5 | 业务规则 | agent 回复时用语音播放，还是只显示文字？如果播放语音，用什么音色？和 083 的 Edge-TTS 复用吗？ | 语音播放（复用 Edge-TTS），用户可选音色 | |
| 6 | 业务规则 | 语音识别（STT）用什么方案？纯本地（Whisper）、纯云端（Azure STT/讯飞）、还是混合？ | 本地 Whisper 做基础识别，云端做兜底（准确率更高） | |
| 7 | 业务规则 | 语音交互和桌面宠物是什么关系？唤醒时宠物是否有动画反馈（竖耳朵/转头）？ | 有 — 唤醒时宠物动画响应，说话时宠物嘴巴动 | |

## 备注

技术参考：
- **STT（语音转文字）**：Whisper（本地）/ Azure Speech（云端）/ 讯飞
- **TTS（文字转语音）**：Edge-TTS（#083 已集成）
- **唤醒词检测**：Porcupine / Snowboy / 本地 VAD + 关键词检测
- **Tauri 麦克风权限**：需要系统级音频输入访问

与现有系统的关系：
- 083 已有 Edge-TTS 集成 → TTS 部分可直接复用
- 084 Agent 生命周期 → 语音唤醒可以作为"交互事件"记录（影响休眠统计）
- 桌面宠物工作区 → 宠物动画可配合语音状态切换
