## 为什么做这个

### 产品定位

> 岛主 = 一个本地运行的、有自主意识的 AI 伙伴。
> 它用自己的智力为用户服务，不等指令，主动思考和行动。
> 用得越久越懂你，永远不会被删除或重置。

### 与市面产品的根本区别

- ChatGPT / Cursor / 飞书 AI：用户不来，AI 就是死的
- **岛主：用户不在的时候，AI 也在为你思考和工作**

### 为什么市面没人做主动式 AI

| 障碍 | 别人做不了 | 岛主能做 |
|------|-----------|---------|
| 成本模型 | 平台 AI 主动工作 = 白烧 token | 用户自付 API 费，AI 多干活直接受益 |
| 无持续上下文 | 云端无状态，memory 很弱 | 本地 SQLite 完整记忆，7×24 运行 |
| 怕打扰 | 大厂推送做不好就是骚扰 | 一对一私人助理，知道全上下文，精准推送 |

**结论：不是做不到，是云端/平台型的商业模型不支持。本地 + 持续运行 + 深度记忆 = 岛主独有的土壤。**

### Token 花在哪里用户觉得值

唯一标准：**AI 帮用户省了比 token 费用更多的时间或钱。**
- ✅ 花 1 块 token 帮你整理了今日待办优先级 → 省了 15 分钟
- ✅ 花 2 块 token 搜索了你关注领域的最新动态 → 省了 30 分钟刷网页
- ✅ "后天周三要交 PRD，审计中心原型还没确认" → 避免了漏 DDL 的风险
- ✅ "3 天前你问了 BA 数据精度的事，还没回复" → 省了翻聊天记录回忆的时间
- ❌ 花 1 块 token 跟你说"今天天气不错" → 没有价值

## 用户故事

**As a** 同时管理多个项目的产品经理
**I want** 打开应用时 AI 管家主动告诉我今天该关注什么、哪些事在等我跟进
**So that** 我不用在脑子里维护所有项目的状态，AI 帮我记着、帮我催着

## 核心循环：感知 → 学习 → 决策 → 行动 → 汇报

```
┌─────────────────────────────────────────┐
│            AI 自主生活循环               │
│                                         │
│  感知 ──→ 学习 ──→ 决策 ──→ 行动 ──→ 汇报
│   ↑                                  │  │
│   └──────────────────────────────────┘  │
│         （用户回来 → 展示成果）          │
└─────────────────────────────────────────┘
```

| 阶段 | 职责 | 数据源 |
|------|------|--------|
| **感知** | 理解用户身份、行为模式、偏好、关注点 | profile、对话历史、工具日志、工作区数据 |
| **学习** | 从错误/撤回中优化、从对话中积累知识 | chat_db、撤回记录、knowledge |
| **决策** | 自主判断"现在该为用户做什么" | 感知结果 + 时间 + 上下文 |
| **行动** | 执行自己决定的任务 | 工具调用（搜索/整理/分析/提醒） |
| **汇报** | 用户打开时主动开口，呈现成果 | 生成问候 + 工作记录 |

## 渐进实施策略

### Phase 1：管家先开口（不花 token，纯逻辑）

**核心变化：** 对话由管家发起，不由用户发起。

- 用户打开应用 → 管家根据时间段 + 待办数据主动说一句话
- 不调 LLM，纯模板拼接（"下午好。你今天有 2 个待办到期。"）
- 结合迭代节奏提示 DDL（"后天周三要交 PRD"）
- 验证点：这个改变是否让用户更愿意打开应用

### Phase 2：用户画像 + 个性化问候（少量 token）

- Onboarding 阶段主动问用户身份（岗位、角色、关注领域、迭代节奏）
- 基于 profile 生成个性化开口（调 LLM，但内容简短）
- 读最近 3-5 条对话做简要复盘
- 了解用户工作节点（Sprint 周期、评审日、上线日）

### Phase 3：后台自主工作（真正的自主循环）

- 用户空闲时 AI 后台执行任务：
  - 检查"发出确认但未收到回复"的事项 → 提醒跟进
  - 检查迭代时间线 → 提前预警 DDL
  - 根据用户事项分类框架，建议"今天该先做什么"
  - 搜索用户关注领域的最新信息
- 用户回来时展示完整工作记录
- AI 自己决定做什么（基于用户画像 + 项目节奏 + 紧急程度判断）

### Phase 4：跨工作区关联分析

- 工作区作为"数据触角"接入外部系统（禅道/Jira/文档）
- AI 做跨源关联分析（"Bug 数上升 + Sprint 延期 → 项目有风险"）
- 岛主成为"唯一能看到你所有项目全貌的 AI"

## 范围（全量，分 Phase 实施）

### 感知能力

- **用户画像收集**：onboarding 主动问 + 对话中逐步推断 + 定时批量丰富
- 分析近 N 天对话，提炼用户高频需求模式
- 发现用户偏好和习惯（活跃时段、常用功能、语言风格）
- 从工作区数据中获取项目状态

### 学习能力

- 用户撤回 → 分析"什么情况下回答不好"，优化服务方式
- 工具调用低效 → 记录高效路径
- 重复被问同样的问题 → 自动创建知识条目

### 决策能力

- AI 自主判断该做什么（有判断力，不是固定规则）
- 考虑因素：用户身份/角色 + 关注点 + 时间规律 + 待办到期
- 冷却机制：不频繁打扰，做过的事不重复做

### 行动能力

- 搜索用户关注领域的最新信息
- 整理/总结对话中的知识和经验
- 检查待办到期并准备提醒
- 检查工作区数据变化
- 用户可配置"AI 空闲时可做的任务类型"

### 汇报能力

- 用户打开应用时（窗口 focus），管家主动开口（Phase 1 起）
- 展示为聊天中的"管家汇报"（可展开看详情）
- AI 工作记录持久化，可回溯查看

## 安全原则

```
AI 自主行动可以做的：
✅ 读取对话历史和日志（只读）
✅ 更新 user_profile（丰富画像）
✅ 添加 knowledge 条目（积累经验）
✅ 清理过期/错误的知识
✅ 使用工具搜索信息
✅ 生成总结和建议
✅ 创建草稿（用户确认后生效）

AI 自主行动不能做的：
❌ 修改源码
❌ 删除用户数据
❌ 修改密钥配置
❌ 代替用户做决定（只建议，不执行高风险操作）
❌ 无限制消耗 API token（每轮有预算上限）
```
