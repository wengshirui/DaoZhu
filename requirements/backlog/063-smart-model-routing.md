## 问题陈述

当前岛主使用单一模型处理所有请求，用户需要手动在设置中切换 Provider。但实际上：
- 简单问题（问候、列表查询）用本地小模型（Ollama）就够了，白花大模型的钱
- 复杂问题（代码生成、多步推理）需要云端大模型（DeepSeek Pro）才能做好
- 用户不知道哪些场景该用哪个模型
- 用户不知道自己电脑能不能跑本地模型

## 用户故事

**As a** 岛主用户
**I want** AI 自动判断我的问题难度并选择合适的模型回答
**So that** 简单问题秒回（本地模型快且免费），复杂问题有质量保证（云端大模型）

## 范围

### In Scope

- 意图分类器：用规则 + 关键词判断请求复杂度（不用 LLM 做分类，太慢）
- 路由策略：简单 → 本地小模型（Ollama）/ 复杂 → 云端大模型（DeepSeek）
- 回退机制：本地模型不可用时自动回退到云端
- 配置：用户可在设置中开关自动路由（默认关，因为需要先配 Ollama）
- 结果标注：回复末尾小字标注使用了哪个模型（让用户感知路由在工作）
- Ollama 可用性检测：启动时探测本地 Ollama 是否运行、有哪些模型可用（原 #020）
- 首次检测建议：检测到本地有 GPU ≥ 8GB 时，建议用户开启本地模型（原 #020）

### Out of Scope

- 模型质量评分系统（初期不做自动评估）
- 多模型并行调用取最优（成本太高）
- 训练/微调本地模型
- 自动安装 Ollama（只做建议，不自动装）

## 验收标准

1. **AC1**: 配置 `ai.smart_routing = true` 后，简单请求（"你好"、"今天几号"）路由到本地模型
2. **AC2**: 复杂请求（"帮我建一个工作区"、涉及工具调用的任务）路由到云端大模型
3. **AC3**: 本地模型（Ollama）不可用时，所有请求自动回退到云端，不报错
4. **AC4**: AI 回复末尾显示模型标注如 "— via deepseek-chat" 或 "— via qwen2.5:7b"
5. **AC5**: 路由规则可通过配置自定义（哪些关键词走大模型、哪些走小模型）
6. **AC6**: 启动时自动探测 Ollama 可用性，设置中展示检测结果（原 #020 AC1）

## 业务价值

- 简单问题响应速度提升 3-5x（本地模型无网络延迟）
- 月度 API 成本预估降低 40-60%（简单问题占比约 50%）
- 为离线场景打基础（Ollama 无需联网）
