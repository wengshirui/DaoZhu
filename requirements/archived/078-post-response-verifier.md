## 问题陈述

#077 的 prompt 级防幻觉（诚实原则 + 质检）不够可靠。实际测试中发现：
- AI 没有调用任何工具，却声称"通过 API 查到 50 条"（实际 71 条）
- 质检只在"生成前"注入提示，模型可以选择性忽略
- Prompt 约束本质是"请求模型诚实"，不能"强制模型诚实"

**参考方案：** hermes-agent 的"文件变异验证器"——在模型回复**之后**由代码追加真实状态，覆盖任何编造。不信任模型会诚实，直接用代码事实覆盖。

**核心思想：代码级后置校验 > prompt 级前置约束。**

## 用户故事

**As a** 岛主用户
**I want** AI 回复中的声明如果与实际工具执行不一致，系统自动追加真实信息
**So that** 即使 AI 编造了"已完成"，我也能看到真实的执行情况

## 范围

### In Scope

- **工具执行结果追踪** — 每轮对话记录所有工具调用的实际结果（成功/失败/未调用）
- **后置校验逻辑** — 模型回复生成后、返回给用户前，代码检查：
  - 回复中声称"已完成/已做了/成功了"但本轮没有成功的工具调用 → 追加警告
  - 回复中提到具体数字但本轮没有调用过查询工具 → 追加"⚠️ 该数字未经工具验证"
  - 本轮有工具失败但回复中未提及 → 追加"⚠️ 注意：XX 工具执行失败"
- **验证器追加格式** — 在回复末尾以明显标记追加（用户可见但不侵入正文）
- **配置开关** — 可在设置中开关（默认开启）

### Out of Scope

- 自动重试（验证器只报告，不修复）
- 阻止输出（不拦截回复，只追加补充）
- 对纯对话（无工具/无数字）的验证

## 验收标准

| # | AC |
|---|-----|
| 1 | 工具调用失败后，AI 回复中若声称"已完成"，回复末尾自动追加"⚠️ 验证器：XX 工具实际执行失败" |
| 2 | AI 回复包含具体数字（如"50 条"）但本轮无查询工具调用时，追加"⚠️ 该数据未经工具验证，可能不准确" |
| 3 | 本轮有工具失败但 AI 回复完全未提及时，追加"⚠️ 注意：本轮 XX 操作未成功" |
| 4 | 纯对话（无工具调用、无数字声明）不触发验证器 |
| 5 | 验证器追加信息用明显视觉区分（如灰色小字/独立区块），不与 AI 正文混淆 |
| 6 | 可通过配置关闭验证器 |

## 技术方向（参考 hermes-agent）

hermes-agent 的实现思路：
1. `_turn_failed_file_mutations` 字典追踪每轮写文件的成功/失败
2. 回复生成后检查：有失败 → 追加 footer
3. Footer 内容来自代码（不是 LLM 生成），100% 准确
4. 用户看到的是："AI 说的 + 代码验证的真实状态"

岛主的适配：
- 已有 `_tool_exec_results` 列表记录每次工具调用结果
- 在 `_stream_final_response` 返回的文本后面追加验证 footer
- 检测逻辑：简单关键词匹配（"已完成"/"成功"/"已帮你"）+ 工具日志比对

## 业务价值

- 彻底解决幻觉问题的最后一公里——prompt 管不住的，代码来管
- 用户信任显著提升："我知道这个 AI 不会骗我，因为系统会帮我核实"
- 与其他 AI 产品形成差异化：岛主有代码级诚实保障
