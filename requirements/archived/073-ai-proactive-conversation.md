## 思想基石

> **用户是谁，他想干什么，怎么帮他更好地实现。**
>
> 这三个问题是岛主所有决策的最高准则。
> AI 的每一次开口、每一个动作，都必须回答这三个问题。
> 不知道用户是谁 → 先去了解；不知道他想干什么 → 从行为推断；知道了 → 主动帮他实现。

---

## 产品定位

> 岛主 = 一个本地运行的、有自主意识的 AI 伙伴。
> 它用自己的智力为用户服务，不等指令，主动思考和行动。
> 用得越久越懂你，永远不会被删除或重置。

**与市面产品的根本区别：**
- ChatGPT / Cursor / 飞书 AI：用户不来，AI 就是死的
- 荣耀 YOYO：做生活助理（取快递/登机牌），宽而浅，绑硬件，数据上云
- **岛主：做工作助理，窄而深，跨平台，完全本地，越用越懂你**

**岛主的护城河：**
1. **本地 + 隐私** — 数据永远在你机器上，不怕泄露和平台倒闭
2. **持续记忆** — 不是每次从零开始，积累几个月甚至几年的上下文
3. **自主行动** — 不等你开口，自己工作、思考、学习

## 为什么市面没人做

| 障碍 | 别人做不了 | 岛主能做 |
|------|-----------|---------|
| 成本模型 | 平台 AI 主动工作 = 白烧 token | 用户自付 API 费，AI 多干活直接受益 |
| 无持续上下文 | 云端无状态，memory 很弱 | 本地 SQLite 完整记忆，7×24 运行 |
| 怕打扰 | 大厂推送做不好就是骚扰 | 一对一私人助理，知道全上下文，精准推送 |

**结论：不是做不到，是云端/平台型的商业模型不支持。本地 + 持续运行 + 深度记忆 = 岛主独有的土壤。**

## 用户故事

**As a** 同时管理多个项目的产品经理
**I want** 打开应用时 AI 管家主动告诉我今天该关注什么、哪些事在等我跟进
**So that** 我不用在脑子里维护所有项目的状态，AI 帮我记着、帮我催着

---

## 核心用户场景

用户画像：产品经理，同时管 4 个项目，两周一个 Sprint，每周多个交叉 DDL。

**核心痛点：脑子里同时跑太多线程。**

| 痛点 | AI 能做什么 | 价值 |
|------|------------|------|
| 忘了下个 DDL | "后天周三要交 PRD，原型还没确认" | 避免漏 DDL |
| 发出确认后忘了跟进 | "3 天前问了 BA 数据精度，还没回复" | 省了翻记录的时间 |
| 不知道今天先做什么 | "建议先处理 UAT 缺陷（被催了），再准备详设评审" | 减少决策疲劳 |
| 迭代开始前忘了检查 | "明天迭代开始，上个迭代有 2 个遗留缺陷未关闭" | 避免遗漏 |
| 切换项目时回忆上下文 | "FDMS 上次跟进到 UAT 阶段，剩 3 个缺陷" | 秒回上下文 |

**Token 花在哪里值：** AI 帮用户省了比 token 费用更多的时间。"后天要交 PRD" 这一句话 = 避免一次事故。

## 核心循环：感知 → 学习 → 决策 → 行动 → 汇报

```
┌─────────────────────────────────────────┐
│            AI 自主生活循环               │
│                                         │
│  感知 ──→ 学习 ──→ 决策 ──→ 行动 ──→ 汇报
│   ↑                                  │  │
│   └──────────────────────────────────┘  │
│         （用户回来 → 主动开口）          │
└─────────────────────────────────────────┘
```

| 阶段 | 职责 | 数据源 |
|------|------|--------|
| **感知** | 理解用户身份、行为模式、偏好、关注点 | profile、对话历史、工具日志、工作区数据 |
| **学习** | 从错误/撤回中优化、从对话中积累知识 | chat_db、撤回记录、knowledge |
| **决策** | 自主判断"现在该为用户做什么" | 感知结果 + 时间 + 上下文 |
| **行动** | 执行自己决定的任务 | 工具调用（搜索/整理/分析/提醒） |
| **汇报** | 用户打开时主动开口，呈现成果 | 生成问候 + 工作记录 |

## 渐进实施策略

### Phase 1：管家先开口（零 token）

**核心变化：** 对话由管家发起。主动打招呼才像人，否则还是机器。

- 用户打开应用 → 管家根据时间段 + 待办数据主动说一句话
- 结合迭代节奏提示 DDL（"后天周三要交 PRD"）
- 不调 LLM，纯模板拼接
- **验证点：** 这个改变是否让用户更愿意打开应用

### Phase 2：了解用户 + 个性化（少量 token）

- Onboarding 主动问用户身份（岗位、角色、关注领域、迭代节奏）
- 基于 profile 生成个性化开口（调 LLM，简短）
- 读最近对话做简要复盘
- 了解用户工作节点（Sprint 周期、评审日、上线日）
- **验证点：** 个性化是否比模板更有粘性

### Phase 3：后台自主工作（完整循环）

- 用户空闲时 AI 后台执行任务：
  - 检查"发出确认但未收到回复"的事项 → 提醒跟进
  - 检查迭代时间线 → 提前预警 DDL
  - 建议"今天该先做什么"（基于用户事项分类框架）
  - 搜索用户关注领域的最新信息
- 用户回来时展示完整工作记录
- AI 自己决定做什么（基于用户画像 + 项目节奏 + 紧急程度判断）
- **验证点：** AI 主动做的事是否真的省了用户时间

### Phase 4：跨工作区关联分析

- 工作区作为"数据触角"接入外部系统（Jira / 禅道 / Confluence）
- AI 做跨源关联分析（"Bug 数上升 + Sprint 延期 → 项目有风险"）
- 岛主成为"唯一能看到你所有项目全貌的 AI"
- **验证点：** 跨源分析是否提供了单一工具无法给出的洞察

## 安全原则

```
AI 自主行动可以做的：
✅ 读取对话历史和日志（只读）
✅ 更新 user_profile（丰富画像）
✅ 添加 knowledge 条目（积累经验）
✅ 清理过期/错误的知识
✅ 使用工具搜索信息
✅ 生成总结和建议
✅ 创建草稿（用户确认后生效）

AI 自主行动不能做的：
❌ 修改源码
❌ 删除用户数据
❌ 修改密钥配置
❌ 代替用户做决定（只建议，不执行高风险操作）
❌ 无限制消耗 API token（每轮有预算上限）
```
