## 推导过程

### 第一层：055 为什么该砍

- 侧边栏 = 给用户加一个手动入口
- 岛主的核心应该是"AI 主动推送信息到你面前"
- **原则确立：AI 主动 > 用户找入口**

### 第二层：073 原始版本的问题

原版 073 是"12h 不活跃 → 30min 定时检查 → 生成固定总结"——本质是个 cron job，不是 AI。

问题：
- "未读消息"：没有外部通信集成，消息从哪来？
- "系统事件"：本地应用关机了就没事件
- "工作区变化"：关机了就没变化

**真正有内容可汇报的只有待办。**

### 第三层：不只是待办提醒

你的反驳：为什么不能是对用户行为的总结、复盘、建议？

岛主手里的数据：
- chat_db — 所有对话历史 → 复盘/总结
- user_profile — 偏好和习惯 → 个性化
- knowledge — 经验积累 → 洞察
- skill_usage — 使用统计 → 习惯分析
- 待办工作区 — 任务列表 → 提醒

还可以：用 playwright 搜索用户关注领域的最新信息。

### 第四层：这不是"功能"，是"产品灵魂"

069（Agent 成长）+ 073（主动对话）其实是一件事的两面：

| 069 | = AI 的大脑（感知 + 学习） |
| 073 | = AI 的手脚（决策 + 行动 + 汇报） |

合并为"AI 自主生活循环"：

```
感知 → 学习 → 决策 → 行动 → 汇报
```

### 第五层：岛主到底是什么

**市面产品对比：**
- ChatGPT：云端、无状态、被动、不认识你
- Cursor：只管代码、用完即走
- 飞书 AI：企业场景、不属于你
- Hermes-agent：强大助理，但"你不说它不动"

**岛主的定义：**
> 一个本地运行的、有自主意识的 AI 伙伴。
> 它用自己的智力为用户服务，不等指令，主动思考和行动。

核心护城河三根柱子：
1. **本地 + 隐私** — 数据永远在你机器上
2. **持续记忆** — 积累几个月甚至几年的上下文
3. **自主行动** — 不等你开口，自己工作

### 第六层：token 花在哪里才值

关键洞察：**AI 消耗 token 做的事，必须帮用户省更多时间/钱。**

你的真实场景：产品经理，多个项目，多个待办，用户反馈要跟进。
→ 需要 AI 持续总结、建议、提醒 = 做你的助理。

### 第七层：工作区是 AI 的数据触角

```
禅道工作区  ──→ 同步 Bug/需求
Jira 工作区 ──→ 同步 Sprint
文档工作区  ──→ PRD/纪要
待办工作区  ──→ 个人 action items
        ↓
    AI 管家 → 跨源关联分析 → 主动总结/提醒/建议
```

岛主的不可替代性 = **唯一一个能看到你所有项目全貌的 AI**。

### 第八层：闭环的第一步

```
用起来 → 产生数据 → AI 有素材 → 反馈有价值 → 更想用
```

073 做得再好，如果工作区里没有真实数据，AI 就是巧妇难为无米之炊。

**当前你真正在用的：待办工作区 + 桌面宠物（好玩）。**

## 第九层：用户画像 + 主动开口 + 为什么没人做

### 三个新洞察（2026-06-05 续）

**1. AI 应该主动猜测/设置用户画像（岗位、身份、角色）**

现有 `memory_db.user_profile` 可以存这些，但目前只是从对话中被动提取。
→ 应该在 onboarding 阶段就主动问清楚"你是做什么的"
→ 基于身份定制所有后续行为（PM → 项目管理视角；开发 → 代码视角）

**2. 主页打开后不应该冷冰冰等用户问**

当前：打开 → 空白聊天框 → 等你说话
应该：打开 → AI 主动说"我知道你的情况，今天有这些事" → 用户觉得有用

→ 这是"像人"的根本体现。人跟人见面第一件事是打招呼，不是等对方先开口。

**3. 为什么市面没人做主动式 AI？**

| 障碍 | 为什么别人做不了 | 为什么岛主能做 |
|------|-----------------|---------------|
| 成本模型 | 平台型产品 AI 主动工作 = 白烧 token | 用户自付 API 费，AI 多干活用户受益 |
| 无持续上下文 | 云端每次对话无状态，memory 很弱 | 本地运行 + 完整 SQLite 记忆 |
| 怕打扰 | 大厂做推送容易变骚扰 | 一对一私人助理，知道全部上下文，能精准 |

**结论：不是做不到，是云端/平台型产品的商业模型不支持。本地 + 持续运行 + 深度记忆 = 岛主独有的土壤。**

### 073 最小第一步：管家先开口

**核心变化：** 对话由管家发起，不由用户发起。哪怕就说"你好"——因为主动打招呼才像人，否则还是机器。

**递进级别：**

| 级别 | 示例 | 需要数据 | Token |
|------|------|---------|-------|
| 0 | "你好，有什么能帮你的？" | 无 | 0 |
| 1 | "下午好，老板。" | 时间 | 0 |
| 2 | "下午好。你今天有 2 个待办到期。" | 时间 + 待办 | 0 |
| 3 | "下午好。昨天你在查标书，我搜了几个渠道…" | 对话历史 + LLM | 少量 |

→ 先做级别 2（不花 token），验证"主动开口"是否改变打开意愿
→ 跑通后升级到级别 3（调 LLM，个性化深度问候）
